# 幻想乡偏爱录

纯前端东方 Project 个人喜爱度排序网站。React 19 + TypeScript 5 + Vite 7 + Tailwind CSS 4；使用 IndexedDB 保存进度，Vitest 和 fast-check 验证排序。无需账户、后端或运行时数据接口。原创 SVG 神社与名字符卡占位；按项目所有者确认的非商业许可接入 dairi 立绘，支持全站开关、全身／半身／近景取景和 100%–300% 缩放。

## 本地运行与部署

需要 Node.js 22.12+（建议当前 LTS）和 npm。

```sh
git clone https://github.com/orznoif-zzz/touhou-character-suki.git
cd touhou-character-suki
npm ci
npm run dev
npm test
npm run data:audit
npm run build
npm run preview
```

按终端显示的本机地址访问。生产产物为 `dist/`，上传至支持静态文件的托管服务即可；构建使用相对资源路径，支持子目录部署。网站没有服务器路由，无需后端。部署后建议 HTTPS。IndexedDB 存档按浏览器和网站来源隔离，换域名、端口或设备前请导出 JSON；清除站点数据会清除存档。

依赖变更时使用 `npm install` 并提交 `package-lock.json`。首次启动不需要 `.env`、API 密钥或数据库配置。

### 静态部署

- Netlify／Cloudflare Pages：导入仓库，构建命令 `npm run build`，输出目录 `dist`，Node.js 22.12+。
- Vercel：选择 Vite，构建命令 `npm run build`，输出目录 `dist`。
- GitHub Pages：在仓库 Settings → Pages 中选择 GitHub Actions；工作流依次执行 checkout、安装 Node.js 22、`npm ci`、`npm run build`，通过官方 `actions/upload-pages-artifact` 上传 `dist`，再用 `actions/deploy-pages` 部署。不要将 `src` 或整个仓库作为站点产物上传。
- 自有服务器：将 `dist` 内的文件整体复制到静态站点目录即可。`npm run preview` 仅用于本机预览构建结果。

仓库没有自动发布工作流，推送代码不会自动创建公网网站。

## 数据及覆盖

当前立绘覆盖 **170 / 203**，缺图清单见 `data/missing-art.json`；图片不会改变数据版本或排序存档。

当前版本收录 **203 位**独立角色；默认游戏范围 **146 位**。整数正作 126、小数作 120、出版物原创 41、PC-98 35、音乐及其他独有 2；分类有重叠，不能相加。64 个作品索引、1508 条作品关联。数据保留来源、首登场、实际登场／提及区分、核验状态和可空图片字段。

主要索引：[THBWiki 官方角色列表](https://thwiki.cc/官方角色列表)。直接请求遭遇 403 后停止该路径访问，使用 [THBWiki-Markdown](https://github.com/Delsin-Yu/THBWiki-Markdown/tree/0ba8d39151572c83a79d9d45a9d0d997f9beb535) 固定快照与可读网页补充锦上京、具名碎片角色。主表 196 项均有处理结论，纯文字索引未对齐项为 0。保留大妖精、小恶魔等稳定称呼；团体、一般敌人、未实装及二设不作为个人角色。

**不能宣称最新官方角色已完整穷尽。** 47 个来源条目未提供可解析的完整出场表，缺失的是登场记录，不是 47 个角色；最新出版物章节仍需逐项复核。快照提交时间不代表事实更新时间。详见 [数据覆盖报告](docs/DATA_COVERAGE.md)、[机器可读报告](docs/coverage.json) 与 [素材调查](docs/ASSETS.md)。

`data/curation.json` 保存身份合并、补充、排除和理由；`data/source-facts.json` 保存提取事实；`src/data/characters.json` 为随构建发布的审核快照。正常构建不联网。重新生成：`npm run data:build`，随后运行审计和测试。维护抓取脚本串行限速并缓存响应，遇到访问限制应停止；不要通过代理等方式绕过。原始缓存位于不提交的 `.cache/`，需维护者主动运行来源获取与提取脚本后才可重建原始事实。

## 排序原理与操作语义

平衡胜者树逐次提取 Top-K。所有角色保留为叶节点，失败者仍可竞争后续名次；每次取出冠军后只使该叶到根的路径失效。固定随机种子决定初始顺序，比较缓存和严格偏好图的传递闭包复用已知关系。明确并列用等价组处理，组间关系必须无环。

2026-10-31 修复：初始排列基于完整参赛名单固定，排除／跳过保留空叶，不重新打乱剩余角色。旧存档中已经由偏好图证明的名次直接识别，避免新旧树布局不同而补问无关的低名次比较。事件格式和数据库版本不变，已有 JSON 可直接恢复。详见 [排序修复说明](docs/SORTING_FIX.md)。

“剩余比较上界”是当前结构下的保守估算，不是保证每次操作都减一的倒计时。排除已经胜出的分支角色需要局部补评，可能少量增加；恢复角色、扩大 Top N 会增加。已确定名次人数不是答题完成百分比；此前证据足够时允许一次确定多名，所有名次都必须有直接或传递证据。

稳定、传递的严格偏好下，可正确获得真正 Top K；询问次数上界为 `n − 1 + (k − 1) × ceil(log₂ n)`。树构建与逐次更新的基础工作量为 O(n + k log n)，但本实现每次操作从事件日志重建派生图及树以确保撤销一致性，传递闭包最坏 O(n³)；不能将人类比较次数上界当作整个程序的 CPU 复杂度。当前 203 人规模适用，更大数据库应增量化图计算。

“两个都喜欢／不喜欢”只记录感受并暂缓该对，不生成胜负，也不自动认定两人同样喜欢。其他分支继续；全部被暂缓时进入待处理界面，需主动重新比较或明确并列。持续不确定时不承诺固定完成次数。“不认识”进入待评池，不表示不喜欢；未补评的结果仅对已评范围成立。“排除”才将角色移出候选。并列跨界保留整组，可能超过 N 人，名次为 1、2、2、4。中途仅显示已证明的名次前缀。

## 存档与模块

事件日志是存档的事实来源；候选、范围、随机种子、目标、数据版本与所有操作随 JSON 保存。比较图和树由日志确定性重建，不重复保存可能失配的派生状态。IndexedDB 保存活动会话及历史；相同会话的历史保存更新其最近快照。localStorage 只用于轻量偏好。写入队列防止快慢写入覆盖。导入拒绝未知版本、未知角色和矛盾日志；数据版本升级暂无自动迁移，多标签页同时编辑暂无冲突协调。

```text
src/domain/       纯函数引擎、类型、存档校验与性质测试
src/data/         静态角色／作品数据库与范围查询
src/components/   设置、对决、结果、素材占位、无障碍弹窗
src/lib/          IndexedDB 存储、独立 Canvas 海报、JSON 导出
data/             来源事实和人工校订
scripts/          导入、转换、审计及比较次数模拟
docs/             覆盖、素材、测试报告
public/assets/characters/   已接入的授权立绘
```

角色 `image` 为空或加载失败均回退原创符卡。图片接入需同时补充作者、原始地址、许可证据、署名与导出许可，具体步骤见素材报告。长榜 PNG 每页最多 20 人，逐页下载。
