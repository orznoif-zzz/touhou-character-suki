# 2026-10-31 排序与可追溯性修复

## 根因

旧实现每次使用 `shuffled(active, seed)` 建树。虽然随机种子固定，但剔除一个元素改变了洗牌输入长度，剩余角色的位置也随之改变。历史比较图没有丢失，已经回答过的同一对不会再次询问，但原本的分支胜者缓存无法继续直接用于新树，产生大量本可避免的新配对。预计剩余次数因此大幅回涨。

原估算还把只有一个有效子树的未解析节点计入比较次数；现在只计两侧均有候选的未解决节点。

## 实现

- 固定原始名单的洗牌位置，排除／跳过用空叶表示，保留其他分支结构；恢复回原位置。
- 并列组锚定到原始固定位置，不因成员退出而全局重排。
- 从偏好图识别已证明胜过全部剩余候选的角色，兼容旧树布局产生的存档，避免已证明的名次退回未完成。
- 估算明确标为“剩余比较上界”；局部分支胜者退出仍可能需要补评，不通过人为截断数字伪造单调进度。
- 新增按角色／文字筛选的完整当前事件记录；可核对任意两人关系及其最短证据链，标记原始操作编号。未知关系直接说明未确定，不生成排名依据。

## 效率回归

专项模拟：172 人，稳定数字全序；遇到指定的后 33 名即排除；先 Top 10 再扩展 Top 20。10 个种子，原版 399–603 次，新版 254–265 次。此为可控模拟，不是对任何真实用户未来选择的预测。排除安排和真实偏好会改变实际次数。

## 验证

- 24 项测试通过，包括 5 项新增回归测试及随机性质测试。
- 覆盖中途排除后的局部修复、撤销、严格选择估算递减、不同树布局的已证明名次、每个输出名次相对所有后续候选的关系证明、带并列和已排除中间角色的证据链。
- 已有实际会话在修复前后得到相同 Top 20，未改动任何历史选择。原始 JSON 仅只读分析，诊断产物保存在不提交的 `artifacts/`。
- `npm run build` 类型检查及生产构建通过。
- Chrome 实际恢复旧 JSON：433 次比较、33 位排除、20 个名次保留；按角色筛选和两步传递证据显示正常。
